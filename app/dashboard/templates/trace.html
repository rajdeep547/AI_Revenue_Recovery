3 · The arithmetic

Every act-or-skip on economics comes from one line of arithmetic: expected value (EV — the average rupee result of an action once the payoff is weighted by how likely it is). The engine acts only when EV clears the floor (the minimum EV, in rupees, fixed in policy as min_ev_inr = {{ d.min_ev_inr }}).

{% if d.is_control %}

This customer is in the control arm, so this arithmetic did not drive the outcome — it is shown only to record what the engine computed. The skip is by experimental design (section 5).

{% endif %}
p_effective = confidence × prior + (1 − confidence) × population_rate
  = {{ d.cc_raw }} × {{ d.prior }} + (1 − {{ d.cc_raw }}) × {{ d.population_rate }}   [× history multiplier {{ d.history_multiplier }}]
  = {{ d.p_effective }}
p_action_basis = min( p_effective × chosen-rung effectiveness {{ d.action_effectiveness }}, 0.95 ) = {{ d.p_action_basis }}
EV = p_action_basis × ticket − action cost
  = {{ d.p_action_basis }} × {{ d.ticket_inr }} − {{ d.action_cost_inr }}
  = {{ d.ev_inr }}
vs floor   {{ d.ev_vs_floor }}

p here is the incremental probability, not the raw one. Incremental means caused by our contact — the extra slice of these failures that recover because we reached out, over and above the customers who would have paid on their own anyway. Most insufficient-funds and downtime failures self-retry and succeed with no help; paying to nudge those buys nothing. Only the incremental slice can repay the cost of the action, so only it belongs in the EV.

decisions.p_incremental_prior, decisions.history_multiplier, decisions.p_effective, decisions.p_action_basis, decisions.action_cost_inr, decisions.ev_inr. population_rate is population_incremental and the floor is min_ev_inr, both from config/decision_policy.json; chosen-rung effectiveness is that file's action_ladder entry. A {{ dash }} means the field is NULL because this decision skipped before any EV was computed.

4 · The ladder

The recovery actions form a fixed ladder — five rungs ordered cheapest first: a silent gateway retry, then email, SMS, WhatsApp, and finally a live agent call. The engine scores every channel-eligible rung's EV on this payment's numbers and takes the best one.

Rung names, cost_inr and effectiveness from config/decision_policy.json → action_ladder.
